# День 19. Композиция MCP-инструментов

## Пайплайн

Запрос «Получи прогноз на три дня для Москвы, кратко подведи итог и сохрани
отчет» выбирает один готовый host-side pipeline. Он последовательно вызывает
три MCP-инструмента:

```text
create_weather_report
  ├─ get_weather_forecast(city, forecast_days)
  │    └─ WeatherForecast: location, days, source…
  ├─ summarize_forecast(forecast: WeatherForecast)
  │    └─ WeatherReportSummary: диапазоны температур, осадки, markdown
  └─ save_weather_report(content, filename)
       └─ SavedWeatherReport: filename, download_url
```

Маршрутизатор запускает pipeline только при явном запросе сохранить отчет.
Обычный вопрос о погоде по-прежнему вызывает только `get_weather_forecast`.
Каждый промежуточный результат остаётся структурированным JSON: сервис передает
ответ первого инструмента как `forecast` второго, а поле `markdown` из ответа
второго — как `content` третьего. Все аргументы и ответы шагов прикладываются к
контексту агента, а заголовок ответа показывает последовательность вызовов.

## Безопасность файла

`save_weather_report` пишет Markdown только в `data/reports/`. Имя ограничено
ASCII-шаблоном `weather-report-….md`, содержимое — 20 000 символами. Приложение
отдаёт файл через авторизуемый API `GET /api/reports/{filename}`; в карточке
ответа доступны скачивание и предпросмотр. Предпросмотр получает Markdown через
`GET /api/reports/{filename}?preview=true` и строит DOM через `textContent`, не
интерпретируя содержимое как HTML. Путь проверяется на выход из выделенной директории.

## Проверка

```bash
PYTHONPATH=. .venv/bin/pytest -q tests/test_weather_mcp.py
```

Покрыто выполнение трех инструментов по порядку, передача структурированного
прогноза в сводку и текста сводки в сохранение, наличие файла и его скачивание.
В тестах вместо сетевого погодного API используется фиксированный прогноз.

## Сценарий видео

1. Открыть `/api/mcp/tools` и показать три инструмента: прогноз, сводку и сохранение.
2. В чате попросить прогноз на три дня для Москвы, краткую сводку и файл отчета.
3. Показать подпись MCP со всеми тремя вызовами и плитку отчета.
4. Открыть предпросмотр, затем скачать файл и показать период, температуры,
   вероятность осадков и источник.
5. Показать код pipeline и тест передачи результатов между инструментами.

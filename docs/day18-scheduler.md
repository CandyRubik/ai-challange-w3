# День 18. Почасовой погодный дашборд

## Что умеет

Каждый час фоновый worker получает прогноз Москвы на следующие 24 часа
и сохраняет все точки прогноза в SQLite. Основной источник — Open-Meteo;
если его Forecast API недоступен с сервера, для Москвы используется wttr.in
с интервалом в 3 часа. Дашборд показывает температуру,
ощущаемую температуру, состояние погоды, вероятность и количество осадков,
скорость ветра, влажность и совет по одежде для каждого часа.

В блоке истории остаются срезы за 72 часа и график температуры. Источник и
интервал прогноза видны на странице. Срезы
показывают данные прогноза, которые были сохранены при каждом запуске, а не
показания метеостанции. Сводка на дашборде агрегирует диапазон температуры,
ощущаемую температуру, максимум осадков и ветра на ближайшие сутки.

Погодный чат использует текущий сохранённый прогноз и историю обновлений как
контекст, хранит свою историю отдельно и работает без пользовательского профиля.
Например: «Как одеться к 18:00?» или «Когда сегодня сильнее всего пойдёт дождь?».

```text
Weather MCP → расписание в SQLite ← погодный worker на VDS
                     ↑                         ↓
             почасовой запрос             Open-Meteo
                     ↓                         ↓
Погодный дашборд ← API ← почасовой прогноз в SQLite
        ↓
Погодный чат ← текущий прогноз + история запусков
```

Источники данных: [Open-Meteo Forecast API](https://open-meteo.com/en/docs) и
[wttr.in JSON API](https://github.com/chubin/wttr.in#data-rich-output-format-v2).

## Запуск

Фоновый сборщик запускается отдельно от stdio MCP-сервера:

```bash
set -a
source .env
set +a
python -m app.scheduler.worker
```

Worker создаёт расписание Москвы с интервалом 60 минут и горизонтом прогноза
24 часа, если база ещё не содержит расписаний. Первый запуск происходит сразу.
Путь к общей базе приложения, MCP-сервера и worker задаётся `CHAT_DB_PATH`;
по умолчанию используется `data/chat.sqlite3`.

На VDS worker запускается как отдельная служба `systemd`, рядом с FastAPI:

```ini
[Unit]
Description=AI Challenge weather scheduler
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=app
WorkingDirectory=/opt/ai-challange-w3
EnvironmentFile=/opt/ai-challange-w3/.env
ExecStart=/opt/ai-challange-w3/.venv/bin/python -m app.scheduler.worker
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

Пример требует подстановки фактического пользователя, пути к checkout и env-файла.
В production env-файл должен включать `APP_ENV=production` и длинный случайный
`APP_PASSWORD`; API проверяет вход по подписанной защищённой cookie. Приложение
следует выставлять наружу только через HTTPS reverse proxy.
Worker атомарно назначает следующий запуск до запроса к погодному API. Если сеть
недоступна, сохраняет ошибку и повторяет сбор через час; перезапуск процесса
подхватывает сохранённое расписание.

## MCP-инструменты

- `create_weather_schedule` — создать почасовой сбор для города;
- `list_weather_schedules` — просмотреть активные и остановленные расписания;
- `cancel_weather_schedule` — остановить расписание;
- `get_weather_summary` — агрегировать ближайшие часы из последнего сохранённого
  прогноза.

Погодная страница открывается кнопкой **Погода** в боковой панели. Интерфейс
перечитывает сохранённые данные раз в минуту; новый прогноз поступает раз в час.
При работе резервного источника точки прогноза идут с шагом 3 часа.

Дашборд и погодный чат доступны после входа владельца, если настроен
`APP_PASSWORD`.

## Видео

1. Открыть **Погода**, показать ближайшие 24 часа, советы по одежде и время последнего сбора.
2. Показать, что worker работает отдельным процессом.
3. Спросить в погодном чате: «Как одеться к 18:00?» и показать ответ по прогнозу.
4. Показать историю срезов и график изменения температуры.
5. Коротко показать `get_weather_summary` и строки сохранённого расписания в SQLite.
